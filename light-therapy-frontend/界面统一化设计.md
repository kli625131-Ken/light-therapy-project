项目界面统一化设计与实现规范（执行版）

版本：v1.0
适用范围：受试者界面光疗系统 / 研究者界面后台管理系统
状态：执行规范（Implementation Ready）

一、背景与目标说明（Why）

当前项目包含两个独立的用户界面体系：

受试者登录界面（光疗系统）

研究者登录界面（后台管理系统）

由于历史演进与功能差异，两套界面在整体布局结构、视觉风格与交互体验上存在不一致问题，增加了用户认知成本，也提高了前端维护与扩展的复杂度。

本次改造目标

在不影响现有业务功能与核心逻辑的前提下，对两套界面进行布局与设计规范的统一化改造，实现：

统一的页面结构框架

统一的视觉与交互风格

明确的角色区分但一致的产品体验

为后续功能扩展、组件复用与技术升级提供稳定基础

二、统一页面结构规范（Layout Specification）
2.1 页面整体结构

所有页面统一采用以下三段式结构：

┌──────────────────────────────┐
│ Header（页面头部信息栏）      │
├──────────────┬───────────────┤
│ Sidebar      │ Main Content  │
│ 左侧导航栏   │ 主内容区      │
└──────────────┴───────────────┘

2.2 页面头部信息栏（Header）
左侧内容

统一显示机构与系统名称组合：

杨浦区精神卫生中心 · 物联网光照 · {系统名称}

其中 {系统名称} 根据用户角色动态显示：

受试者界面：光疗系统

研究者界面：后台管理系统

右侧内容

当前登录用户信息（姓名 / 角色）

退出登录按钮

Header 在两个系统中保持高度、布局、交互一致，仅文案与用户信息动态变化。

2.3 左侧导航栏（Sidebar）

固定于页面左侧  占比要小于Main，要求完美的比例；

采用统一的：

宽度

背景色

字体与图标风格

展开 / 高亮 / 悬浮交互逻辑

根据用户角色动态加载对应菜单项：


2.4 主内容区（Main Content）

位于页面中部右侧  占比要大于导航栏，要求完美的比例；

用于承载各功能模块页面

统一内容区：

内边距（padding）

最大宽度 / 自适应规则

页面切换与加载反馈方式

三、设计规范要求（Design System）
3.1 色彩系统（Color System）

定义统一的：

主色（Primary）

辅助色（Secondary）

中性色（文字 / 边框 / 背景）

状态色（成功 / 警告 / 错误）

两个系统共享同一套颜色变量，禁止各自定义独立色值


3.2 组件风格（UI Components）

以下基础组件需保持风格与交互一致：

按钮（Button）

表单项（Input / Select / DatePicker）

卡片（Card）

表格（Table）

弹窗 / 抽屉（Modal / Drawer）

所有组件统一交互反馈（hover / active / disabled / loading）

3.3 响应式设计（Responsive）

支持：

桌面端

平板

移动端

保证在不同分辨率下：

页面结构不破坏

导航与内容可正常访问

关键操作不丢失

四、实现要求（Implementation Requirements）
4.1 功能与业务约束

不删除、不削弱、不改变现有业务功能

仅调整布局结构与视觉呈现层

业务逻辑、接口调用、权限控制保持不变

五、验收标准（Acceptance Criteria）
5.1 一致性标准

两个系统整体视觉风格一致性 ≥ 90%

页面结构、组件样式无明显差异


5.2 响应式与兼容性

桌面 / 平板 / 手机端显示正常

无阻断性体验问题
