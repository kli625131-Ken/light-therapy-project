# Trae + Git 项目代码管理规则（强制版）

> 本文档用于 **约束 Trae 在项目中的代码生成、修改、删除、重构行为**，
> 目标是：
> - 不破坏 Git 历史
> - 不污染仓库结构
> - 可追溯、可回滚、可协作
> - 适合长期演进与多人协同

---

## 0. 适用范围（必须遵守）

- 本项目所有 **代码编写 / 修改 / 删除 / 重构** 行为
- 所有 **由 Trae 直接或间接生成的代码**
- 前端 / 后端 / 文档 / 脚本

**默认前提：**
- 使用 Git 管理代码
- 使用 `dev` 作为日常开发分支
- `main` 为稳定分支（只通过合并进入）

---

## 1. 基本总原则（最高优先级）

### 1.1 Trae 不得直接操作 Git

❌ 禁止 Trae：
- 执行 `git add / commit / push / reset / rebase`
- 修改 `.git` 目录

✅ Trae 只能：
- **修改工作区文件**
- **提出 Git 操作建议（文字说明）**

> Git 操作 **只能由人执行**。

---

### 1.2 所有改动必须“可解释”

Trae 生成或修改代码时，**必须同时给出：**

- 改动目的
- 改动范围
- 是否为破坏性修改（Breaking Change）

**禁止：**
- 无说明的大面积重写
- “我帮你优化了一下”式模糊表述

---

## 2. 文件与目录操作规则

### 2.1 新建文件 / 文件夹

Trae 新建文件时，必须明确说明：

- 文件路径
- 文件用途
- 是否为长期文件 or 临时文件

示例（合规）：
```text
新增文件：light-therapy-frontend/src/utils/date.ts
用途：统一日期格式化工具
影响范围：前端公共工具层
```

---

### 2.2 删除文件（高风险操作）

❌ Trae **不得直接删除文件**

✅ 正确流程：
1. Trae 标记：**建议删除**
2. 说明：
   - 文件用途
   - 是否被引用
   - 删除风险
3. 等待人工确认

---

### 2.3 禁止修改的目录

Trae **不得修改 / 生成内容到以下目录**：

```text
.git/
node_modules/
dist/
build/
.vite/
.idea/
.vscode/
```

---

## 3. 代码修改规则

### 3.1 单一职责原则（强制）

一次 Trae 操作：

- 只能做 **一类事情**

❌ 错误示例：
- 同时重构 + 改逻辑 + 改目录结构

✅ 正确示例：
- 只做接口抽象
- 只做命名规范调整

---

### 3.2 修改必须最小化

Trae 修改代码时必须遵循：

- 不相关代码 **不得改动**
- 格式变化需说明原因

优先级顺序：
1. 修 bug
2. 保持原结构
3. 最小 diff

---

## 4. 重构规则（重点）

### 4.1 重构前置说明（必须）

Trae 在任何重构前，必须输出：

- 当前结构问题
- 重构目标
- 重构步骤
- 是否影响对外接口

**未给出以上说明 = 不允许执行重构**

---

### 4.2 重构拆分规则

复杂重构必须拆分为：

1. 结构调整（不改逻辑）
2. 逻辑重构（不改行为）
3. 行为调整（明确 Breaking Change）

每一步 **都应对应一次 Git commit**。

---

## 5. 文档与注释规范

### 5.1 Trae 生成代码必须自解释

- 复杂逻辑必须有注释
- 公共方法必须说明用途

禁止：
- 魔法数字
- 不可读缩写

---

### 5.2 文档放置规则

```text
docs/        # 项目文档
scripts/     # 自动化脚本
README.md    # 项目入口说明
```

Trae 不得将说明文档散落在代码目录。

---

## 6. 与 Git 的协作规则（核心）

### 6.1 Trae 输出必须可 commit

每次代码输出，必须满足：

- 可独立提交
- 不依赖隐藏上下文
- 不混合多种目的

---

### 6.2 Commit Message 建议格式（Trae 需遵守）

```text
feat: 新功能
fix: 修复 bug
refactor: 重构（不改行为）
chore: 杂项 / 配置 / 忽略规则
docs: 文档
```

Trae 输出时应建议对应类型。

---

## 7. AI 失控兜底规则

### 7.1 出现以下情况，立即中止 Trae 操作

- 大量无关文件被改动
- 目录结构被重写
- 无法解释的逻辑变化

立即执行：
```bash
git restore .
```

---

## 8. 最终裁决原则（写给人）

> **Trae 是“受控开发者”，不是项目负责人。**

- 架构决策 → 人
- 合并代码 → 人
- 发布上线 → 人

Trae 只负责：

> **高质量、可控、可回滚的代码生产。**
